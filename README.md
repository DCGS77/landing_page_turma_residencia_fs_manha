# Landing Page da Turma | Residência Full Stack 5.0 (Manhã)

Landing page oficial da turma da manhã da **Residência Full Stack 5.0**, programa do **Instituto Eldorado** em parceria com a **Petrobrás** (agosto a dezembro de 2026).

O objetivo do projeto é apresentar a turma, os residentes e a jornada de aprendizado, e também praticar o desenvolvimento colaborativo usando **Agile methodologies** (metodologias ágeis), com cada aluno responsável por uma parte da entrega.

## 📌 Documentação & Requisitos

- 📑 **Especificação de Requisitos:** Veja o documento detalhado em [docs/REQUISITOS.md](docs/REQUISITOS.md).

## 🎯 Objetivos

- Construir uma landing page (página de apresentação) da turma
- Praticar trabalho em equipe com Git e GitHub
- Aplicar práticas ágeis: divisão de tarefas, entregas incrementais e revisão entre pares
- Exercitar o fluxo de **branches** (ramificações), **commits** e **Pull Requests** (solicitações de integração)

## 🛠️ Tecnologias

- HTML5
- CSS3
- JavaScript
- Git e GitHub
- Figma (prototipação)

> Ajustar conforme a stack (conjunto de tecnologias) definida pela turma.

## 🔄 Metodologia de trabalho

O projeto segue uma abordagem baseada em **Scrum** e **Kanban**:

- **Backlog** (lista de tarefas pendentes): todas as funcionalidades e seções da página são registradas como **Issues** (tarefas) no GitHub
- **Kanban board** (quadro de tarefas): acompanhamento no GitHub Projects com as colunas *To Do*, *In Progress*, *In Review* e *Done*
- **Sprints** (ciclos curtos de entrega): a definir pela turma
- Cada residente assume uma ou mais Issues e é responsável pela entrega dela

## 🌿 Fluxo de contribuição

1. Escolha uma Issue no quadro e atribua a você
2. Atualize sua branch `main` local: `git pull origin main`
3. Crie uma branch para a sua tarefa: `git checkout -b feature/nome-da-tarefa`
4. Faça commits pequenos e com mensagens claras
5. Envie a branch: `git push origin feature/nome-da-tarefa`
6. Abra um Pull Request vinculado à Issue (ex.: `Closes #12`)
7. Aguarde a **code review** (revisão de código) de pelo menos um colega antes do **merge** (integração)

### Padrão de nomes de branch

- `feature/` nova seção ou funcionalidade
- `fix/` correção de erro
- `docs/` documentação
- `style/` ajustes visuais sem mudança de lógica

### Padrão de mensagens de commit

Seguindo o **Conventional Commits** (padrão convencional de commits):

- `feat: adiciona seção de residentes`
- `fix: corrige alinhamento do menu no mobile`
- `docs: atualiza README`
- `style: ajusta cores do header`
